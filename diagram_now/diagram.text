================================================================================
เอกสารรวบรวมข้อมูล Data Flow Diagram (DFD)
โครงการ: ระบบสแกนใบหน้าและติดตามการใช้ทรัพยากรคอมพิวเตอร์สำหรับการสอบในห้องปฏิบัติการ
(Face recognition and PC resource monitoring system for lab exams)
อัปเดตล่าสุด: DFD Level 0 - Level 2 (Reordered)
================================================================================

--------------------------------------------------------------------------------
1. องค์ประกอบหลัก (Main Components)
--------------------------------------------------------------------------------
[External Entities - ผู้เกี่ยวข้องภายนอก]
1. อาจารย์ (Teacher)
2. นักศึกษา (Student)

[Data Stores - แหล่งเก็บข้อมูล]
D1: ข้อมูลผู้ใช้งาน (Users)
D2: ข้อมูลการสอบและกฎระเบียบ (Exams & Rules)
D3: ข้อมูลอัตลักษณ์ใบหน้า (Face Data)
D4: ข้อมูลการเข้าสอบและบันทึกเหตุการณ์ (Sessions & Logs)

--------------------------------------------------------------------------------
2. Data Flow Diagram Level 0 (Context Diagram)
--------------------------------------------------------------------------------
[System Process: 0.0 ระบบสแกนใบหน้าและติดตามการใช้ทรัพยากรคอมพิวเตอร์ฯ]

A. ฝั่งอาจารย์ (Teacher)
   [Input -> ระบบ]
   - ข้อมูลบัญชีผู้ใช้เพื่อยืนยันตัวตน
   - ข้อมูลการตั้งค่าห้องสอบและผังที่นั่ง
   - ข้อมูลกำหนดการสอบและรายวิชา
   - รายการโปรแกรมและเว็บไซต์ต้องห้าม
   - คำสั่งเปิด/ปิดเซสชันการสอบ

   [ระบบ -> Output]
   - ผลการตรวจสอบและสิทธิ์การเข้าสอบ
   - Dashboard แสดงสถานะผู้เข้าสอบแบบ Real-time
   - การแจ้งเตือนการทุจริต/ละเมิดกฎ
   - ข้อมูล Log การใช้งานทรัพยากรของผู้เข้าสอบ
   - รายงานสรุปผลการเข้าสอบท้ายวิชา

B. ฝั่งนักศึกษา (Student)
   [Input -> ระบบ]
   - ข้อมูลบัญชีผู้ใช้เพื่อยืนยันตัวตน
   - ข้อมูลภาพใบหน้าต้นฉบับสำหรับลงทะเบียน
   - ข้อมูลภาพใบหน้าปัจจุบันเพื่อเข้าห้องสอบ
   - ข้อมูล Process, Active Window และ System Resources

   [ระบบ -> Output]
   - ผลการตรวจสอบและสิทธิ์การเข้าสอบ
   - ผลการลงทะเบียนสำเร็จ
   - สถานะยืนยันตัวตนผ่าน
   - ข้อความแจ้งเตือนเมื่อทำผิดกฎ
   - ข้อมูลเลขที่นั่งสอบที่ได้รับจัดสรร

--------------------------------------------------------------------------------
3. Data Flow Diagram Level 1 (Main Processes)
--------------------------------------------------------------------------------
*หมายเหตุ: เรียงลำดับใหม่ตามความต้องการล่าสุด

Process 1.0: จัดการการลงทะเบียนอัตลักษณ์ใบหน้า
Process 2.0: จัดการการยืนยันตัวตนก่อนเข้าห้องสอบ
Process 3.0: จัดการการตรวจสอบสภาพแวดล้อมและโปรแกรม
Process 4.0: จัดการข้อมูลผู้ใช้งานและการตรวจสอบสิทธิ์
Process 5.0: จัดการข้อมูลการสอบและทรัพยากรต้องห้าม
Process 6.0: จัดการเซสชันการเข้าสอบและการรายงาน

--------------------------------------------------------------------------------
4. Data Flow Diagram Level 2 (Sub-Processes & Data Flows)
--------------------------------------------------------------------------------
*รูปแบบ: ฝั่งซ้าย (External/Process) | ฝั่งขวา (Data Store)

==================================================
Process 1.0: จัดการการลงทะเบียนอัตลักษณ์ใบหน้า
==================================================

[1.1 ตรวจสอบคุณภาพและตำแหน่งใบหน้า]
   (ซ้าย เข้า) ข้อมูลภาพใบหน้าต้นฉบับสำหรับลงทะเบียน [จาก นักศึกษา]
   (ซ้าย ออก) ข้อความแจ้งเตือนให้จัดตำแหน่งใบหน้าใหม่ [ไป นักศึกษา]
   (ภายใน)   ผลการตรวจสอบคุณภาพใบหน้า -> ส่งไป 1.2

[1.2 ทดสอบความเป็นบุคคลจริง (Liveness Check)]
   (ซ้าย เข้า) ข้อมูลการขยับใบหน้าทดสอบความเป็นบุคคลจริง [จาก นักศึกษา]
   (ภายใน)   รับ ผลการตรวจสอบคุณภาพใบหน้า [จาก 1.1] -> ส่ง ผลการทดสอบความเป็นบุคคลจริง ไป 1.3

[1.3 บันทึกข้อมูลอัตลักษณ์ใบหน้า]
   (ซ้าย ออก) ผลการลงทะเบียนสำเร็จ [ไป นักศึกษา]
   (ขวา ออก)  ข้อมูลภาพอัตลักษณ์ใบหน้าที่ลงทะเบียน [ไป D3]
   (ภายใน)   รับ ผลการทดสอบความเป็นบุคคลจริง [จาก 1.2]

==================================================
Process 2.0: จัดการการยืนยันตัวตนก่อนเข้าห้องสอบ
==================================================

[2.1 ตรวจจับและแปลงข้อมูลใบหน้า]
   (ซ้าย เข้า) ข้อมูลภาพใบหน้าปัจจุบันเพื่อเข้าห้องสอบ [จาก นักศึกษา]
   (ภายใน)   ข้อมูลรหัสลักษณะใบหน้า (Face Descriptor) -> ส่งไป 2.2

[2.2 เปรียบเทียบใบหน้ากับฐานข้อมูล]
   (ขวา เข้า)  ข้อมูลใบหน้าต้นฉบับสำหรับยืนยันตัวตน [จาก D3]
   (ภายใน)   รับ ข้อมูลรหัสลักษณะใบหน้า [จาก 2.1] -> ส่ง ผลการเปรียบเทียบใบหน้า ไป 2.3

[2.3 ตรวจสอบสิทธิ์การเข้าสอบ]
   (ซ้าย ออก) สถานะยืนยันตัวตนผ่าน [ไป Process 6.0]
   (ซ้าย ออก) ข้อความปฏิเสธการเข้าสอบ [ไป นักศึกษา]
   (ภายใน)   รับ ผลการเปรียบเทียบใบหน้า [จาก 2.2]

==================================================
Process 3.0: จัดการการตรวจสอบสภาพแวดล้อมและโปรแกรม
==================================================

[3.1 ตรวจสอบรายการโปรแกรมที่ทำงานอยู่]
   (ซ้าย เข้า) ข้อมูล Process, Active Window และ System Resources [จาก นักศึกษา]
   (ภายใน)   รายการโปรแกรมที่กำลังทำงาน -> ส่งไป 3.2

[3.2 ตรวจสอบเทียบกับกฎระเบียบห้องสอบ]
   (ขวา เข้า)  รายการโปรแกรมต้องห้ามสำหรับการตรวจสอบ [จาก D2]
   (ภายใน)   รับ รายการโปรแกรมที่กำลังทำงาน [จาก 3.1] -> ส่ง ข้อมูลรายการโปรแกรมที่ละเมิดกฎ ไป 3.3

[3.3 แจ้งเตือนและดำเนินการเมื่อพบการละเมิด]
   (ซ้าย ออก) ข้อความแจ้งเตือนเมื่อทำผิดกฎ [ไป นักศึกษา]
   (ซ้าย ออก) ข้อมูลการละเมิดกฎ [ไป Process 6.0]
   (ขวา ออก)  บันทึกข้อมูลการละเมิดกฎระเบียบ [ไป D4]
   (ภายใน)   รับ ข้อมูลรายการโปรแกรมที่ละเมิดกฎ [จาก 3.2]

==================================================
Process 4.0: จัดการข้อมูลผู้ใช้งานและการตรวจสอบสิทธิ์
==================================================

[4.1 ตรวจสอบข้อมูลบัญชีผู้ใช้]
   (ซ้าย เข้า) ข้อมูลบัญชีผู้ใช้เพื่อยืนยันตัวตน [จาก นศ./อ.]
   (ขวา เข้า)  ข้อมูลบัญชีและรหัสผ่านของผู้ใช้งาน [จาก D1]
   (ภายใน)   ผลการยืนยันตัวตนที่ถูกต้อง -> ส่งไป 4.2

[4.2 ตรวจสอบระดับสิทธิ์ผู้ใช้งาน]
   (ซ้าย ออก) ผลการตรวจสอบและสิทธิ์การเข้าสอบ [ไป นศ./อ.]
   (ขวา เข้า)  รายละเอียดสิทธิ์การใช้งาน [จาก D1]
   (ขวา ออก)  สถานะการเข้าใช้งานที่ต้องการอัปเดต [ไป D1]
   (ภายใน)   รับ ผลการยืนยันตัวตนที่ถูกต้อง [จาก 4.1]

==================================================
Process 5.0: จัดการข้อมูลการสอบและทรัพยากรต้องห้าม
==================================================

[5.1 สร้างและแก้ไขข้อมูลห้องสอบ]
   (ซ้าย เข้า) ข้อมูลการตั้งค่าห้องสอบและผังที่นั่ง [จาก อาจารย์]
   (ขวา ออก)  ข้อมูลห้องสอบที่สร้างใหม่ [ไป D2]

[5.2 กำหนดรายละเอียดวิชาสอบ]
   (ซ้าย เข้า) ข้อมูลกำหนดการสอบและรายวิชา [จาก อาจารย์]
   (ขวา ออก)  รายละเอียดวิชาสอบที่สร้างใหม่ [ไป D2]

[5.3 กำหนดรายการโปรแกรมต้องห้าม]
   (ซ้าย เข้า) รายการโปรแกรมและเว็บไซต์ต้องห้าม [จาก อาจารย์]
   (ขวา ออก)  รายการสิ่งต้องห้ามที่สร้างใหม่ [ไป D2]

==================================================
Process 6.0: จัดการเซสชันการเข้าสอบและการรายงาน
==================================================

[6.1 ควบคุมสถานะเซสชันการสอบ]
   (ซ้าย เข้า) คำสั่งเปิด/ปิดเซสชันการสอบ [จาก อาจารย์]
   (ขวา ออก)  สถานะการสอบที่ต้องการอัปเดต [ไป D2]

[6.2 จัดสรรที่นั่งสอบ]
   (ซ้าย เข้า) สถานะยืนยันตัวตนผ่าน [จาก Process 2.3]
   (ซ้าย ออก) ข้อมูลเลขที่นั่งสอบที่ได้รับจัดสรร [ไป นักศึกษา]
   (ขวา เข้า)  ข้อมูลผังที่นั่งสำหรับการจัดสรร [จาก D2]
   (ขวา ออก)  ข้อมูลการลงทะเบียนเข้าสอบในเซสชัน [ไป D4]

[6.3 ติดตามและรายงานผลการสอบ]
   (ซ้าย เข้า) ข้อมูลการละเมิดกฎ [จาก Process 3.3]
   (ซ้าย ออก) Dashboard แสดงสถานะผู้เข้าสอบแบบ Real-time [ไป อาจารย์]
   (ซ้าย ออก) รายงานสรุปผลการเข้าสอบท้ายวิชา [ไป อาจารย์]
   (ขวา เข้า)  ข้อมูลสถานะผู้สอบและประวัติการทุจริตทั้งหมด [จาก D4]

5. Entity-Relationship Diagram (ERD)
--------------------------------------------------------------------------------
*หมายเหตุ: โครงสร้างฐานข้อมูลจาก Supabase (รวมทั้งหมด 10 Tables)

[1. Entity: Profiles] (ข้อมูลผู้ใช้งาน - เชื่อมโยง Auth)
- id (PK, UUID)
- user_id (FK -> auth.users)
- full_name
- student_id
- role
- face_images (JSON)
- created_at
- updated_at

[2. Entity: User_Photos] (เก็บ URL รูปภาพใบหน้าสำหรับลงทะเบียน)
- id (PK, UUID)
- user_id (FK -> auth.users)
- face_forward (URL)
- open_eye (URL)
- closed_eye (URL)
- turn_left (URL)
- turn_right (URL)
- look_up (URL)
- look_down (URL)
- move_close (URL)
- updated_at
*Relationship: Profiles (1) --<มีข้อมูล>-- (1) User_Photos (ผ่าน user_id)

[3. Entity: Room_Seat_Layouts] (ผังที่นั่งห้องสอบ)
- id (PK, UUID)
- room_name
- rows
- columns
- total_seats
- created_by (FK -> auth.users)
*Relationship: Profiles (1) --<สร้าง>-- (N) Room_Seat_Layouts

[4. Entity: Room_Seat_Ip_Mappings] (การจับคู่ที่นั่งกับ IP Address)
- id (PK, UUID)
- layout_id (FK -> Room_Seat_Layouts.id)
- row_number
- column_number
- seat_number
- ip_address
- mac_address
*Relationship: Room_Seat_Layouts (1) --<ประกอบด้วย>-- (N) Room_Seat_Ip_Mappings

[5. Entity: Exam_Rooms] (ตารางสอบ/การกำหนดวิชาสอบ)
- id (PK, UUID)
- room_name (Ref -> Room_Seat_Layouts.room_name)
- course_code
- course_name
- section
- exam_date
- exam_time
- start_time
- end_time
- capacity
- is_active
- created_by (FK -> auth.users)
- created_by_name
*Relationship: Profiles (1) --<สร้าง>-- (N) Exam_Rooms
*Relationship: Room_Seat_Layouts (1) --<ถูกใช้ใน>-- (N) Exam_Rooms (Link via name)

[6. Entity: Room_Blocked_Resources] (รายการโปรแกรมต้องห้าม)
- id (PK, UUID)
- room_id (FK -> Exam_Rooms.id)
- pattern (ชื่อโปรแกรม/Process)
- match_type (exact, contains)
*Relationship: Exam_Rooms (1) --<มีรายการ>-- (N) Room_Blocked_Resources

[7. Entity: Exam_Student_Sessions] (เซสชันการเข้าสอบของนักศึกษา)
- id (PK, UUID)
- layout_id (FK -> Room_Seat_Layouts.id)
- student_email
- student_name
- seat_number
- ip_address (Inet)
- face_descriptor (Text)
- is_active
- session_start_time
- session_end_time
- student_profile_url
*Relationship: Room_Seat_Layouts (1) --<รองรับ>-- (N) Exam_Student_Sessions
*Relationship: Profiles (1) --<เข้าสอบใน>-- (N) Exam_Student_Sessions (ผ่าน Email)

[8. Entity: Resource_Logs] (บันทึกทรัพยากรเครื่องของผู้เข้าสอบ)
- id (PK, UUID)
- session_id (FK -> Exam_Student_Sessions.id)
- timestamp
- cpu_usage, cpu_model, ram_usage, ram_total_gb
- ram_used_gb, ram_available_gb, disk_partitions_info
- active_window_title, all_open_windows
- exe_processes, network_download_mb, network_upload_mb
*Relationship: Exam_Student_Sessions (1) --<สร้าง>-- (N) Resource_Logs

[9. Entity: Violation_Logs] (บันทึกการละเมิดกฎ)
- id (PK, UUID)
- session_id (FK -> Exam_Student_Sessions.id)
- violation_type
- resource_name
- action_taken
- details
- timestamp
*Relationship: Exam_Student_Sessions (1) --<ตรวจพบ>-- (N) Violation_Logs

[10. Entity: Qr_Authentication] (ระบบยืนยันตัวตนผ่านมือถือ)
- id (PK, UUID)
- user_id (FK -> auth.users)
- status (authenticated)
- ip
- authenticated_at
- expires_at
*Relationship: Profiles (1) --<ทำรายการ>-- (1) Qr_Authentication

6. Data Flow Description (รายละเอียดข้อมูลไหล)
--------------------------------------------------------------------------------

Data Flow ID : 0001
Data Flow Name : ข้อมูลภาพใบหน้าสำหรับลงทะเบียน
Description : ข้อมูลภาพใบหน้าสำหรับลงทะเบียน
Source : นักศึกษา
Destination : Process 1.0
Type Of Data Flow : หน้าจอ/กล้อง
Data Structure : ข้อมูลภาพใบหน้าสำหรับลงทะเบียน = ภาพใบหน้า + จุดพิกัดใบหน้า + คะแนนคุณภาพ

Data Flow ID : 0002
Data Flow Name : ผลการลงทะเบียนสำเร็จ
Description : ผลการลงทะเบียนสำเร็จ
Source : Process 1.0
Destination : นักศึกษา
Type Of Data Flow : หน้าจอ
Data Structure : ผลการลงทะเบียนสำเร็จ = สถานะความสำเร็จ + เวลาที่บันทึก + URL สำหรับเปลี่ยนหน้า

Data Flow ID : 0003
Data Flow Name : ข้อมูลอัตลักษณ์ใบหน้าที่บันทึก
Description : ข้อมูลอัตลักษณ์ใบหน้าที่บันทึก
Source : Process 1.0
Destination : Data Store D3 (Face Data)
Type Of Data Flow : ฐานข้อมูล
Data Structure : ข้อมูลอัตลักษณ์ใบหน้าที่บันทึก = รหัสผู้ใช้งาน + URL รูปหน้าตรง + URL รูปลืมตา + URL รูปหลับตา + URL รูปหันซ้าย + URL รูปหันขวา + วันที่แก้ไขล่าสุด

Data Flow ID : 0004
Data Flow Name : ข้อมูลภาพใบหน้าเพื่อเข้าห้องสอบ
Description : ข้อมูลภาพใบหน้าเพื่อเข้าห้องสอบ
Source : นักศึกษา

8. Process Specification (รายละเอียดประมวลผล)

Process Number : 1.0
Process Name : จัดการการลงทะเบียนอัตลักษณ์ใบหน้า
Description : เป็น Process หลักที่ทำหน้าที่รับข้อมูลภาพใบหน้า ตรวจสอบคุณภาพ และบันทึกอัตลักษณ์สำหรับใช้ในการยืนยันตัวตน
Input Data Flow : ข้อมูลภาพใบหน้าต้นฉบับสำหรับลงทะเบียน (ซ้าย/ขวา/หน้าตรง/ลืมตา)
Out put Data Flow : ผลการลงทะเบียนสำเร็จ, ข้อความแจ้งเตือน
Process Type : Online Processing
Process Logic : 
IF ได้รับคำขอลงทะเบียนใบหน้าจากนักศึกษา THEN
    เรียกใช้ Process 1.1 ตรวจสอบคุณภาพและตำแหน่งใบหน้า
    IF คุณภาพใบหน้าผ่านเกณฑ์ THEN
        เรียกใช้ Process 1.2 ทดสอบความเป็นบุคคลจริง (Liveness Check)
        IF ผ่านการทดสอบ Liveness THEN
            เรียกใช้ Process 1.3 บันทึกข้อมูลอัตลักษณ์ใบหน้า
        ELSE
            แสดงข้อความแจ้งเตือน "กรุณาทดสอบใหม่"
        ENDIF
    ELSE
        แสดงข้อความแจ้งเตือน "จัดวางใบหน้าไม่ถูกต้อง"
    ENDIF
ENDIF

Process Number : 1.1
Process Name : ตรวจสอบคุณภาพและตำแหน่งใบหน้า
Description : เป็น Process ย่อยที่ใช้ AI (Face-API) เพื่อตรวจสอบว่ามีใบหน้าในเฟรมหรือไม่ และตำแหน่งองศาหน้าถูกต้องตามกำหนด
Input Data Flow : ข้อมูลภาพใบหน้าต้นฉบับสำหรับลงทะเบียน
Out put Data Flow : ผลการตรวจสอบคุณภาพใบหน้า, ข้อความแจ้งเตือนให้จัดตำแหน่งใบหน้าใหม่
Process Type : Online Processing (Real-time)
Process Logic :
รับภาพจากกล้อง Webcam
ตรวจสอบ Face Detection Score
IF ไม่พบใบหน้า OR พบมากกว่า 1 ใบหน้า THEN
    ส่งข้อความแจ้งเตือน "กรุณาอยู่หน้ากล้องเพียงคนเดียว"
ELSE
    คำนวณองศาใบหน้า (Pitch, Yaw, Roll)
    IF องศาใบหน้าตรงกับท่าทางที่กำหนก (เช่น หน้าตรง, หันซ้าย) THEN
        ส่ง "ผลการตรวจสอบคุณภาพใบหน้า" ไปยัง Process 1.2
    ELSE
        ส่งข้อความแจ้งเตือนให้หันหน้าตามคำสั่ง
    ENDIF
ENDIF

Process Number : 1.2
Process Name : ทดสอบความเป็นบุคคลจริง (Liveness Check)
Description : เป็น Process ย่อยที่ตรวจสอบการขยับของใบหน้าเพื่อป้องกันการใช้รูปถ่าย (Anti-spoofing)
Input Data Flow : ข้อมูลการขยับใบหน้าทดสอบความเป็นบุคคลจริง, ผลการตรวจสอบคุณภาพใบหน้า (จาก 1.1)
Out put Data Flow : ผลการทดสอบความเป็นบุคคลจริง
Process Type : Online Processing
Process Logic :
รับค่า Face Landmarks อย่างต่อเนื่อง
คำนวณค่า Eye Aspect Ratio (EAR) หรือ Face Rotation
IF มีการกระพริบตา (EAR < Threshold) หรือมีการหันหน้าจริง THEN
    กำหนดสถานะเป็น "Human Detected"
    ส่ง "ผลการทดสอบความเป็นบุคคลจริง" ไปยัง Process 1.3
ELSE
    รอการขยับใบหน้าต่อไป
ENDIF

Process Number : 1.3
Process Name : บันทึกข้อมูลอัตลักษณ์ใบหน้า
Description : เป็น Process ย่อยที่ทำการอัปโหลดรูปภาพขึ้น Cloud Storage และบันทึก URL ลงฐานข้อมูล
Input Data Flow : ผลการทดสอบความเป็นบุคคลจริง
Out put Data Flow : ข้อมูลภาพอัตลักษณ์ใบหน้าที่ลงทะเบียน (ไป D3), ผลการลงทะเบียนสำเร็จ
Process Type : Online Processing
Process Logic :
รับภาพใบหน้าที่ผ่านการตรวจสอบ (Blob Data)
อัปโหลดไฟล์ภาพไปยัง Supabase Storage (Bucket: user-photos)
รับ URL ของไฟล์ภาพที่อัปโหลดสำเร็จ
บันทึก URL และรหัสผู้ใช้งานลงใน Table 'user_photos' (D3)
ส่งสถานะ "ผลการลงทะเบียนสำเร็จ" กลับไปยังผู้ใช้งาน

Process Number : 2.0
Process Name : จัดการการยืนยันตัวตนก่อนเข้าห้องสอบ
Description : เป็น Process หลักสำหรับตรวจสอบใบหน้าผู้เข้าสอบเพื่อยืนยันว่าเป็นบุคคลเดียวกันกับที่ลงทะเบียนไว้
Input Data Flow : ข้อมูลภาพใบหน้าปัจจุบันเพื่อเข้าห้องสอบ
Out put Data Flow : สถานะยืนยันตัวตนผ่าน, ข้อความปฏิเสธการเข้าสอบ
Process Type : Online Processing
Process Logic :
IF ได้รับรูปถ่ายจากกล้องหน้าห้องสอบ THEN
    เรียกใช้ Process 2.1 ตรวจจับและแปลงข้อมูลใบหน้า
    IF สามารถแปลงข้อมูลใบหน้าได้ (Face Descriptor) THEN
        เรียกใช้ Process 2.2 เปรียบเทียบใบหน้ากับฐานข้อมูล
        เรียกใช้ Process 2.3 ตรวจสอบสิทธิ์การเข้าสอบ
    ELSE
        แสดงข้อความ "ไม่พบใบหน้าหรือใบหน้าไม่ชัดเจน"
    ENDIF
ENDIF

Process Number : 2.1
Process Name : ตรวจจับและแปลงข้อมูลใบหน้า
Description : ใช้ AI ในการตรวจจับตำแหน่งใบหน้าในภาพและแปลงเป็นรหัสตัวเลข (Vector/Descriptor)
Input Data Flow : ข้อมูลภาพใบหน้าปัจจุบันเพื่อเข้าห้องสอบ
Out put Data Flow : ข้อมูลรหัสลักษณะใบหน้า (Face Descriptor)
Process Type : Online Processing
Process Logic :
รับภาพจากกล้อง Webcam
ใช้ Face Detection Model ตรวจหาใบหน้า
IF พบใบหน้า THEN
    ใช้ Face Recognition Model คำนวณค่า Face Descriptor (128-float array)
    ส่งข้อมูล "Face Descriptor" ไปยัง Process 2.2
ELSE
    แจ้งข้อผิดพลาดกลับไปยังผู้ใช้งาน
ENDIF

Process Number : 2.2
Process Name : เปรียบเทียบใบหน้ากับฐานข้อมูล
Description : เปรียบเทียบรหัสลักษณะใบหน้าที่ได้กับข้อมูลต้นฉบับในฐานข้อมูล
Input Data Flow : ข้อมูลรหัสลักษณะใบหน้า (จาก 2.1), ข้อมูลใบหน้าต้นฉบับสำหรับยืนยันตัวตน (จาก D3)
Out put Data Flow : ผลการเปรียบเทียบใบหน้า (Euclidean Distance)
Process Type : Online Processing
Process Logic :
ดึงข้อมูล Face Descriptor ต้นฉบับของผู้ใช้ (จาก D3)
คำนวณระยะห่าง (Euclidean Distance) ระหว่าง Descriptor ปัจจุบัน กับ ต้นฉบับ
IF Distance < Threshold (0.50) THEN
    ผลการเปรียบเทียบ = "MATCH"
ELSE
    ผลการเปรียบเทียบ = "NOT MATCH"
ENDIF
ส่ง "ผลการเปรียบเทียบใบหน้า" ไปยัง Process 2.3

10. Table List (รายการแฟ้มข้อมูล/ตาราง)

*หมายเหตุ: ชื่อไฟล์ในที่นี้คือชื่อ Table ในฐานข้อมูล Supabase

ไฟล์ที่ : 1
ชื่อไฟล์ : profiles
ความหมาย : เก็บข้อมูลผู้ใช้งานเพิ่มเติม (ชื่อ, รหัสนักศึกษา, รูปใบหน้า JSON) เชื่อมโยงกับ auth.users

ไฟล์ที่ : 2
ชื่อไฟล์ : user_photos
ความหมาย : เก็บข้อมูล URL ของรูปภาพใบหน้าแบบแยกคอลัมน์ (หน้าตรง, หันซ้าย, หันขวา ฯลฯ) สำหรับลงทะเบียน

ไฟล์ที่ : 3
ชื่อไฟล์ : room_seat_layouts
ความหมาย : เก็บข้อมูลโครงสร้างผังห้องสอบ ขนาด (แถวxคอลัมน์) และชื่อห้องปฏิบัติการ

ไฟล์ที่ : 4
ชื่อไฟล์ : room_seat_ip_mappings
ความหมาย : เก็บข้อมูลการจับคู่ Mapping ระหว่างเลขที่นั่ง (Row/Col) กับหมายเลข IP Address

ไฟล์ที่ : 5
ชื่อไฟล์ : exam_rooms
ความหมาย : เก็บข้อมูลรายวิชาที่เปิดสอบ กำหนดการสอบ และความเชื่อมโยงกับห้องสอบ

ไฟล์ที่ : 6
ชื่อไฟล์ : room_blocked_resources
ความหมาย : เก็บข้อมูลรายการโปรแกรม ชื่อหน้าต่าง หรือเว็บไซต์ที่ไม่อนุญาตให้ใช้งานระหว่างสอบ

ไฟล์ที่ : 7
ชื่อไฟล์ : exam_student_sessions
ความหมาย : เก็บข้อมูลสถานะ Session การเข้าสอบปัจจุบันของนักศึกษาแต่ละคนแบบ Real-time

ไฟล์ที่ : 8
ชื่อไฟล์ : resource_logs
ความหมาย : เก็บประวัติ Log การใช้งานทรัพยากรเครื่อง (CPU, RAM, Network) ของผู้เข้าสอบอย่างละเอียด

ไฟล์ที่ : 9
ชื่อไฟล์ : violation_logs
ความหมาย : เก็บประวัติการกระทำผิดกฎระเบียบ รายละเอียดการละเมิด และหลักฐานรูปภาพ

ไฟล์ที่ : 10
ชื่อไฟล์ : qr_authentication
ความหมาย : เก็บข้อมูลการยืนยันตัวตนชั่วคราวผ่านมือถือ (QR Code) สำหรับการเข้าสู่ระบบแบบไร้สัมผัส
